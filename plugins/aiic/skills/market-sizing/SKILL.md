# 市场规模：广度 × 强度 × 频度

把一个明确需求转成可复算、可追溯、可验证的年度金额。方法来自《2026-09-19_需求分析课_v4.pdf》的规模部分及用户指定口径，不用行业报告总额或「先取一个市场份额」替代底层拆解。

## 统一公式

**年规模 ＝ 广度 × 强度 × 频度。**

- **广度：有多少人。** 总人口 × 一年内的用户渗透率。
- **强度：每次值多少钱。** 单次实付金额，或单次广告价值。
- **频度：一年发生几次。** 每位年度用户的年使用 / 消费次数。
- **品牌渗透率算品牌规模，赛道渗透率算赛道规模。**

记 `B = N × r`，`R = B × I × F`。在人口口径下，单位须能约掉：

```text
N〔人〕× r〔无量纲〕× I〔元/人次〕× F〔人次/人/年〕 = R〔元/年〕
```

`N` 是声明的地域和人群边界内的总人口，不一定是全国人口。企业场景若按客户企业计费，可把统计主体改成企业，但须显式写明这一操作化扩展，并使 B、I、F 同时使用企业 / 企业消费次口径，不能拿 HR 人数乘企业合同额。

## 执行

### 1. 先锁定边界

明确「用户 × 场景 × 动机」、地域、年份或年度窗口、币种、赛道还是品牌，以及算用户实付、交易金额、广告投放金额还是企业收入。列出影响结果的重要排除项。

若已给出明确产品或人群，不擅自换需求来做大数字。需求未定义时，先形成最小定义；可以复用可用的 `aiic:demand-analysis`，但本 skill 不依赖它存在。缺失信息可用显式假设推进，或只追问会实质改变口径的内容。

### 2. 分别估计 N、r、I、F

为每项列出 **数值或范围、单位、地域与时间、分母、来源、证据状态、怎样验证**。区分原始数据、用户给定值、课程教学假设和本次分析假设。

**广度 B：** 用年度去重人数；分母与渗透率必须来自同一范围。潜在人口不等于实际年度用户，累计注册数、下载数、DAU、MAU 也不等于年度用户。直接获得合格年度用户数时，可用 `N = 已知年度用户数、r = 1` 作计算输入，明确这是等价输入而不是总体渗透率 100%。

直接付费业务优先把 B 定义为年度付费消费者，r 为「总体中的年度付费渗透率」。若从年度使用渗透率再乘付费转化率，后者的分母必须是前者筛出的年度用户。**付费率只出现一次。** 课件 AI 面试案例原本把付费率放在强度栏，本 skill 按用户指定口径等价重组到广度，不改变原算式结果。

**强度 I：** 定义「一次」，再定金额。按次收费取实际成交均价，按人就餐取整桌实付除以用餐人数。订阅业务取一次实际账期付款；买断业务取一次购买金额，不能把使用次数当购买次数。广告业务可拆为「每次使用中的计费曝光量 × 每千次曝光价格 ÷ 1000」。免费用户、折扣、退款、税费、平台分成按所选金额口径处理，不能默默混用。

**频度 F：** 必须属于 B 里的同一批年度用户，并与 I 使用同一个事件。付费者的年购买次数、订阅者的实际付费账期数、年度用户的年会话次数不能互换。季节性需求也可在一个窗口内重复消费；不得将旺季或短期留存样本的频度直接乘全年。

复杂计费、广告、DAU/MAU 转换、分群和去重时，读 [口径与计算指南](references/calculation-guide.md)。

### 3. 计算并审计

展示 `N → r → B → I → F → R` 的代入过程，至少保留一个从人口到年度金额的完整推演。用计算器、Python 或附带脚本复算，不凭心算把「万」「亿」、百分比或 CPM 换算略过去。

多个互斥或已去重的子市场可逐项计算后相加。不同商业模式若覆盖同一用户，只能在确认金额流不重叠时相加，并注明用户重叠；不能直接把各品牌年度用户相加当赛道去重人数。**低 / 中 / 高情景是替代情景，不相加。**

不把品牌规模标成赛道规模，不把交易额当平台收入，不把收入当利润。行业报告与公司披露可作同口径交叉检查；不一致时解释定义与数据差异，不反向调整参数迎合外部总额。

原材料公式、标题或表格冲突时，分别保留「原文声称」和「按给定参数计算」，指出差异；不要替资料悄悄改参数。课程案例与已识别冲突见 [课程案例与来源注意](references/course-cases.md)。

### 4. 情景、敏感性与验证

根据证据给出合理范围，或明确只有演示情景。不要仅为凑齐低 / 中 / 高三档而编造“可信区间”。指出最影响判断、证据最弱且值得验证的参数，并做单因素变化；同时改变多项时，称为组合情景。

这个乘法模型中，其他项不变时各因子的相同比例变化带来相同比例的规模变化。某个参数更值得研究，通常来自它的未知范围、数据质量或决策影响，不是因为公式天然更偏爱它。

沿用课件的验证思路：人口口径查统计材料；年度渗透率用合适的年度调查或记录；频度用完整窗口日志、交易或票据回访；强度用真实成交或广告计费数据。MVP 样本不自动代表总体，不把早期高意愿用户线性外推成总体渗透率。

### 5. 解释规模的含义

将结论限定在已计算的需求和假设内。区分当前规模、未来渗透情景和具体品牌可能取得的收入；不要用未来成熟状态冒充当期事实，也不要由一个窄人群情景断言整个行业上限。

用户需要机会判断时，补充课件的「是否会成为独立赛道」：分别考察基础模型与现有平台 / 行业头部是否可能内置该能力，以及是否存在独立购买与持续交付的理由。这是另一项商业判断，不是从 R 数值自动推出的结论。

规模不足时，可讨论课件提出的改变用户、场景 / 动机或增加人工服务，但明确这是 **新的需求或商业模式假设**，需重新测 N、r、I、F；不能只调高单价而默认其他因素不变。纯计算任务不自动扩展成转型建议。

## 输出与工具

通常输出：口径说明、参数及证据表、完整演算、结果与范围、主要不确定性和验证动作。完整报告可使用 [测算工作表](references/report-template.md)；只要求验算时，直接给公式、结果和口径问题。

附带的标准库脚本 `${CLAUDE_SKILL_DIR}/scripts/size_market.py` 支持多组独立情景、分项连乘、万元 / 亿元换算、范围校验及原文金额比对，不自动汇总情景。准备输入或运行它前，读 [计算器输入说明](references/calculator.md)。脚本验证数字与结构，不验证数据真实性、分母语义、单位约分或人群去重。

实际测算需要当前外部数据时，使用可用工具检索并保留来源和日期；没有工具或数据时，交付有标记的假设情景与缺口，不能声称已实测。用户要求仅依据所给材料时，保留材料边界；本 skill 内的课堂数字不是可直接套用的最新行业数据。

交付前检查：年度、地域、币种一致吗？r 的分母正确吗？付费率重复了吗？I 与 F 的“一次”相同吗？F 是否条件于 B？品牌和赛道混了吗？多群体、多收入流或多情景重复了吗？所有关键输入有来源或假设标签吗？结果是否声称了超过证据支持的精度与范围？
