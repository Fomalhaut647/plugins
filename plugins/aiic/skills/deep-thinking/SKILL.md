# 深度思考

对一个问题连续做四次思考，每一次都在上一次的结论上再推进一层：

| 次序 | 名称 | 做什么 |
|---|---|---|
| 第一次 | 浅层思考 | 写下直觉答案，作为基准线 |
| 第二次 | 广度 + 深度 | 把相关主体和理论工具全部展开，再挑重要的不断追问，抓住根本 |
| 第三次 | 跨度 | 跨地域找类似情况做比较，跨时间看来路和去向 |
| 第四次 | 高度 | 泛化、抽象出规律，沉淀成可复用的思维模型 |

为什么要这样做：表面信息的背后有更深一层的逻辑，找到问题最关键的那个点，对做选择有重大价值。直觉给出的第一个答案通常停在表面（「乘客脾气不好」），对应的解法也停在表面（「贴宣传标语」）。四次思考的每一步都是在强迫分析离开表面。

对某一步该写成什么样没有把握时，读 `references/wanzhou-bus-case.md`。那是课程里的完整示范，展示了四次思考各自的产出。

## 开始之前：把问题问清楚

把用户的问题改写成一到两个明确的问句，写在分析的最前面。

- 事件或现象类的问题通常是两问：「为什么会发生？」和「怎样解决或避免？」
- 选择类的问题通常是：「该怎么选？」和「决定这个选择的判断是什么？」

问题过于宽泛或指代不清，而且不同的读法会导向完全不同的分析时，先向用户确认一句。除此之外直接开始，不要为了稳妥而反复确认。

问题的范围有几种取法、但不值得为此打断用户时（例如「学生」指哪个学段），自行选定一个范围，并在「问题」一行里写明这个假设，让用户知道分析针对的是什么。

## 第一次：浅层思考

写下不经展开的第一反应：原因是什么，怎么解决。几条即可。

这一步是基准线，后面每一次思考都要拿它来对比，才能看出深度思考到底改变了什么。所以要如实写：不要把后面才会想到的内容提前放进来，那样对比就失去了意义；也不要故意写得很差。

## 第二次：广度 + 深度

这是全篇的主体，篇幅应当最多。

### 广度：不漏

广度的目的是不遗漏，每一项用一两句话即可，最后标出哪几项最要紧。分两个方向展开。

**相关主体**。列出所有与问题有关的主体，不只是当事人，还包括旁观者、相关的物（产品、设施、工具）、组织、社会环境、法律法规和规章制度。对每个主体提出与它的角色对应的问题：

- 行动者：为什么这么做？为什么敢这么做？
- 本可以阻止的人：有责任吗？能防止吗？为什么没有做？
- 物和组织：能防止吗？为什么没能防止？
- 环境和规则：是否影响了这件事，或者能够影响这件事？有没有明确的规则？管得住吗？

**理论工具**。把下面的学科视角逐个过一遍，判断哪些与本问题相关，各自能解释什么。不相关的一句话带过。

| 工具 | 适用的情形 |
|---|---|
| 心理学 | 涉及人的行为、群体的行为 |
| 经济学 | 涉及经济利益、成本和代价 |
| 社会学 | 涉及大众行为、道德和价值观 |
| 法学 | 涉及严重损害他人、群体或社会利益的行为 |
| 工程 | 涉及产品或服务的改变、提升和原因分析 |
| 政治 | 涉及国家之间、政党、利益群体 |
| 历史 | 涉及此前发生过的相关内容 |
| 传播学 | 涉及产品或信息的扩散 |

这张表不是封闭的，问题需要时可以加入别的学科。

### 深度：抓住根本

从广度里挑出最重要的一到三项深挖。方法是不断追问、不断否定、不断比较：

1. 给出一个答案。
2. 追问它。为什么有了这个因素就足以导致结果？这个因素是真的吗，怎么证明？同样具备这个因素的其他对象，为什么没有出现同样的结果？
3. 反思这个答案是否还成立。不成立就否定它，换一个答案，回到第 2 步。

一直做到某个答案经得起追问为止。把被否定的答案和否定它的理由也写出来，读者需要看到推理的过程，而不只是终点。

示范：

> 问：Anthropic 为什么成为 AI 领先者？
> 答：有最优秀的工程师。
> 追问：为什么有最优秀的工程师就可以？他们的工程师比 OpenAI、Google 的更优秀吗，怎么证明？优秀工程师的数量应该没有另外两家多吧？
> 反思：这个答案不成立。
> 再答：选对了方向（编程），并且做成了。
> 追问：真的是因为 AI 编程的成功才领先的吗？其他家也做了 AI 编程，为什么是它成功？
> ……

深挖时最常用的是两个视角：

- **心理学（个体，人性）**。行动是心理活动的外在表现，所以要问当事人在想什么、为什么这么想、怎样做出决定。每个人都优先考虑自身利益；当自身利益与群体利益冲突时，约束他的是道德和法律，要追问这些约束为什么没有起作用。
- **社会学（群体，规则）**。人身处群体之中，受群体约束。为什么有人有恃无恐？为什么没有人站出来？现有的相关道德和法律是什么样的，生效了吗，为什么失效？相关的价值观是怎样形成和固化的？这里要记住「存在的就是合理的，合理的也是当下的」：现状有它的成因，但这个成因只在当下的条件里成立。

### 第二次结论

- **关键点**：用一句话写出来，通常可以写成「如何让……」。关键点只有一个或极少数。并列地列出一堆因素，等于还没有找到关键点。
- **限制条件**：关键点之外的其余因素。它们不决定问题是否发生，但会约束方案怎样落地，简要列出即可。
- **解决方案**：围绕关键点展开，按见效的快慢分成三类：慢过程（如观念、素质的改变）、快过程（如规则、法律的制定）、辅助过程（其他环节的改进）。

用户只问「为什么」而没有问「怎么办」时，把「解决方案」连同小标题一起改写成「什么会改变这个局面」，仍按慢过程、快过程、辅助过程展开。

## 第三次：跨度

### 地域跨度

其他地方有没有类似的情况？分三类去找：和我们一样的、比我们好的、比我们差的。他们各自是怎么处理的？

把差异比较出来之后，再追问差异从何而来，并尝试把差异抽象成一组对立的概念。示范案例里，各国对干扰驾驶的处理差异被抽象成「惩罚行为」与「惩罚结果」，并进一步联系到经济发展阶段。

「地域」按问题来取：可以是国家和地区，也可以是不同的行业、公司或人群。

### 时间跨度

站在现在看这件事：过去是怎样的？为什么会发展到现在这样？将来会怎样？

结合心理、经济、社会所处的发展阶段来推演，并给出对未来的预测，包括解决方案会怎样落地、事情往哪个方向发展。要理解：没有最好的做法，只有适合当下的做法。

如果问题涉及的事件已经过去，并且后续发展是已知的，用后续的事实来检验前面的预测。

### 事实要可靠

跨度这一步依赖事实，例如各地的实际做法、历史上的经过。拿不准的事实，有搜索工具时先查证；无法查证的，在文中标明「未经核实」。优先查证结论所依赖的那几条事实，只起举例作用的细节标注即可。编出来的对比会把后面的结论全部带偏，所以宁可少写一条，也不要写一条不确定却说得很肯定的。

### 第三次结论

- **修改**：第二次的分析和方案被改动了什么。如果几乎没有改动，照实写。这说明第二次的结论经受住了跨地域、跨时间的检验，本身就是有价值的信息，不需要为了显得有进展而硬造改动。
- **收获**：通过差异比较和发展阶段的思考，得到了哪些新的理解。

## 第四次：高度

回答三个问题：

1. 从抽象的角度，能够把本问题分析并解释清楚吗？
2. 它会影响其他领域吗？会牵涉到更广泛的经济和社会问题吗？
3. 能不能抽象出更高阶的规律，使本问题只是这条规律的一个案例？

产出三样东西：

- **规律**：用脱离本案例的语言写出几条结论，说清楚谁影响谁、谁决定谁。
- **印证**：这条规律是否有已有的理论或研究支持。说得出就说；说不出就明说这是本次分析得出的假说。不要编造文献或研究结论。
- **迁移**：用这条规律去解释两三个别的问题。解释得通，才说明抽象到位了；解释不通，说明规律还带着本案例的特殊性，需要再改。

这一步的产出是可以带走的思维模型。慢思考练出来的模型，下一次遇到同类问题时就成为快思考，这是做第四次思考的原因。

## 不同类型问题的调整

框架的四次结构不变，每一步里具体问什么要随问题类型调整。

| 类型 | 例子 | 调整 |
|---|---|---|
| 事件、现象 | 为什么生育率降低 | 按上面的标准流程 |
| 选择 | 要不要辞职创业 | 主体是受这个选择影响的人，包括未来的自己；地域跨度看做过类似选择的不同人群，处境相同的、更好的、更差的各有什么结果；时间跨度看这个选择在一年、五年、十年后的样子；关键点是决定选择的那一个判断 |
| 困境、思辨 | 「电车难题」的困境 | 主体是各方立场；深度是追问每种立场所依赖的前提；跨度看不同文化、不同时代如何回答；高度是指出困境背后是哪两种原则在冲突 |

## 输出格式

用用户提问的语言输出，按下面的结构组织。四次思考要按顺序写，不要把最终结论提到最前面：第一次的直觉答案必须在深入分析之前写下，它才是真实的基准线。

```markdown
# 深度思考：<问题>

**问题**：<改写后的一到两个问句>

## 第一次思考：直觉答案
原因、解决

## 第二次思考：广度与深度
### 广度：相关主体
### 广度：理论工具
### 深度：追问到根本
### 第二次结论
关键点、限制条件、解决方案（慢过程、快过程、辅助过程）

## 第三次思考：地域与时间
### 地域跨度
### 时间跨度
### 第三次结论
修改、收获

## 第四次思考：抽象拔高
规律、印证、迁移

## 总结
直觉答案与最终答案的对比；最终结论；可以带走的思维模型
```

「广度：相关主体」和「广度：理论工具」适合用表格；深度部分用连续的问答，保留追问和否定的过程。

## 用户想自己练习时

用户表示想自己思考、一步一步来，或者是在做课堂练习时，不要一次给出全部分析。每次思考先请用户说出自己的答案，再指出遗漏的主体或工具，并用追问的方式推动用户深挖，然后进入下一次。目的是帮用户建立自己的思维模型，而不是替用户想完。
