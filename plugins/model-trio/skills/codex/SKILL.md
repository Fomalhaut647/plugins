# 交给 Codex

用 `mcp__plugin_model-trio_peers__codex` 工具。Codex 干活严谨，但只看得到 `task` 和 `cwd` 下的文件，运行中无法对话，所以任务书要一次写全。

- **写代码**（`mode: write`）。用户没有指定交哪一部分时，只交接口已经定死、和页面无关的独立模块：成块的后端、算法、数据处理、性能。小修改、几十行的改动、要和页面来回对接口的功能，以及前端和视觉，自己做。
  - 接口、验收标准、要一起改的同类都写进 `task`。
  - Codex 的沙箱不联网、只能写 `cwd`，也不提交：装依赖、要联网的测试、提交推送由你做。
  - 交回后读 diff、自己运行测试，通过了才算完成。要它返工或追加时用 `session_id` 续接。
- **审查**（`mode: review`）。`task` 写审查范围和希望重点看的地方。逐条对照代码复核它的发现，不成立的丢掉并说明理由。成立的分两级：会丢数据、算错钱、越权、发错消息或让发布出事故，并且说得出具体怎么发生的，必须修；其余只作建议，列给用户，不修。只审一轮，修完不自动再审。
- **只读调研**（`mode: read`）。查 bug 的原因、要第二意见时用。
- 模型和思考强度默认用用户的 Codex 设置，用户指定了才传 `model`、`effort`。
- Codex 出错或额度用完时告诉用户，不自行换别的办法代替。
