# agent-team

> [English version](README.en.md)

一个 Claude Code plugin：在桌面端让当前会话当主会话，把一件较大的工作拆给多个并行子会话分头完成。主会话负责拆分、分派任务、定验收清单、核实、审查判定和合并，实现代码由子会话写，审查默认交给本机的 Codex 命令行。

它基于 Claude Code 桌面端 2026 年 10 月的并行会话更新：主会话可以直接开子会话，子会话各有独立的工作树和分支，挂在主会话下面，结束时自动回报。它**不**使用官方实验性的 agent teams 功能（那个只在 CLI 里可用）。

## 要求

- Claude Code 桌面端（Code 标签页），会话里有 `start_session`、`list_events`、`SendMessage` 等子会话工具。CLI 里没有这些工具，本 plugin 不可用。
- 项目是 git 仓库：子会话靠 git 工作树隔离。
- 本机装好 Codex 命令行并登录：默认由它审查（改用 Claude 审查时不需要）；查看 Codex 的进度需要 python3。

## 安装

本 plugin 通过 [`fomalhaut647-plugins`](../..) marketplace 分发：

```
/plugin marketplace add Fomalhaut647/plugins
/plugin install agent-team@fomalhaut647-plugins
```

本地开发（marketplace 未推到远端）时，把 GitHub 路径换成 marketplace 仓库的绝对路径：

```
/plugin marketplace add <marketplace 仓库绝对路径>
/plugin install agent-team@fomalhaut647-plugins
```

## 用法

手动调用 `/agent-team:lead`，后面写上要做的事，比如「/agent-team:lead 完成 C 线的 C2、C3、C4 三张卡」（只能手动调用，说「开个团队」之类的话不会触发）。主会话会：

1. **拆分**：拆成互不依赖、改动文件不重叠的几块，太大的卡再拆小；有依赖的块等前一块通过后，从它的分支切出再开工。
2. **开会话**：在你发消息的这一轮，把整次要用的会话一次开好：每块一个开发会话，另加一个整合修复会话，各用独立工作树，思考强度默认 high；审查交给 Codex，不开会话。没轮到的会话只待命、什么都不读，中途不用你点卡片。
3. **先定验收清单**：每个开发会话先交一份验收清单（要做到的行为、适用的红线、明确不管什么、拿不准的产品问题），主会话核对后才写代码。会改变产品行为的问题汇总成一条消息问你，每个附建议，并发通知提醒；你说过「不用问我」的，它按建议定，最后列出来供你否决。
4. **开发与核实**：清单每条都要有自动测试；主会话自己跑一遍测试，确认改动没有越界。
5. **审查一次**：每块只审一次，由本机的 Codex 用它自带的审查模式只读审查，对照验收清单逐条核对。主会话按固定标准分拣：违反清单、碰红线、有具体出错场景的严重问题挡合并；清单没规定的设计问题按第 3 步定下来；其余全部记进标着「审查遗留」的 Issue，这一轮不修。
6. **小修，用测试复核**：挡合并的问题交回开发会话，先写一条修复前会失败的测试，再做最小修改；复核看测试，不再审查；复核没过就打回去再修一次。需要整类重做或改结构的，排成单独一块。
7. **预算和熔断**：每块审查一次，修复最多两次，第二次只在第一次复核没过时才有。还过不了就停下这块，其他块照常推进，主会话带着几个选项和建议找你；碰红线的问题绝不带着合并。
8. **整合与合并**：全部块通过后不再问你，直接把各分支合进主会话的分支，跑全部测试，再由 Codex 整合审查一次，专看块与块的衔接和各块的修复；这一阶段查出的问题交给整合修复会话，在合并后的分支上修，不再叫醒各块原来的开发会话；通过后开一个总 PR，向你汇报每张卡哪些行为已被测试证明、哪些没验证、替你做了哪些决定、遗留问题和 PR 链接。

想看进度随时问一句，主会话用一屏回答每块在哪一步、预算用了多少、大约还要多久。每次汇报的第一句都先写整件任务是否已结案，未结案就写还差什么、在等谁；问你和汇报时，提到的东西先用一句话说清是什么，不假定你记得设计文档和任务卡。每次协调的状态文件（每块的进度、预算、定下的事、每条发现的去向，开发交给 Codex 时还有用时和用量）留在 `~/.claude/plugins/data/agent-team-fomalhaut647-plugins/runs/`，以主会话的会话编号命名，供事后复盘。主会话每次被唤醒时，还会自动归档已经用不上的子会话：读完发现的审查会话（审查由 Claude 做时才有）、结论已经转告你的调研会话、所负责的块已经通过的开发会话、整合审查通过后的整合修复会话。

积下的遗留问题，隔一段时间（比如每个阶段交接时）调用「/agent-team:lead 清理审查遗留问题」清一次：先对照最新代码复核、关掉过时的，再按根源归类处理，反复出现的类加上自动检查，教训写回设计文档或项目规则。

审查和整合审查默认交给本机的 Codex 命令行，换一家模型来审；默认用 gpt-6.1-sol 模型、xhigh 思考强度、开 Fast 模式，调用时写明了就按你写的。Codex 审查时只能读取，审完由后台脚本唤醒主会话；审查很快，不设心跳。想改用 Claude 审查（比如本机没装 Codex），调用时加一句「审查用 Claude」，每块和整合各开一个 Claude 审查会话，用内置 `code-review` 审。

想进一步节省 Claude 的额度，调用时加一句「开发用 Codex」：每块的开发改由 Codex 完成，审查和整合审查改由 Claude 的审查会话做。Codex 开发时只能写入这块的工作副本（可以联网），不提交、不推送；它完成后，运行全量测试、未通过时交回它修复，都由后台脚本完成，之后才唤醒主会话。Codex 开发期间，主会话每隔 55 分钟被心跳唤醒一次、只回一句话，免得它的提示缓存过期。

Codex 出错或额度用完时，这块停下并通知你，不会悄悄改用 Claude。

## 设计取舍

- **只有主会话一侧的 skill**：子会话是完整的桌面会话，平台已经规定了它怎么提交、回报和发消息；它该守的规则写在任务书里，不需要再给它一个 skill。
- **只管做什么，不管怎么做**：主会话看得到其他 skill 的简介、看不到正文，转述它们的用法会被子会话当成权威而执行走样。要改变子会话的默认做法时，必须明说是覆盖并给出理由。
- **完成看验收清单，审查不当终点**：找问题的审查总能报出东西，内置 `code-review` 的 high 档本来就是宁可多报、不复核、每次最多 10 条。拿「审到没有严重问题」当终点，两次真实协调的 11 块里没有一块等到过，审查修复一轮接一轮。
- **每块只审一次，按固定标准分拣**：第一轮审查找到的几乎都是真缺陷；之后各轮要修的，七到九成出自上一轮的修复或没修全。凭感觉挑「严重的」，口径每轮都在漂。
- **先定验收清单**：没定的设计留到修复循环里边修边定，审查会一轮轮加码；开工前问清楚，只问一次。
- **小修，用测试复核**：修复一旦放大成重新设计，就会带出下一轮的问题；最小修改加一条修复前会失败的测试，复核就不用再审一轮。
- **预算和熔断**：循环必须有终止条件；卡住的块停下来换条路，不拖住整次任务。
- **整合审查**：块与块交界处的问题，块内审查看不到；修复的代码也在这一次被独立审过。
- **整合的修复交给新会话**：等到整合审查时，开发会话多半已闲置一个多小时，提示缓存过期，叫醒要重写整份长上下文；衔接问题又常横跨几块。所以块一通过就归档开发会话，整合阶段的问题交给开工时预开的整合修复会话，在合并后的分支上一并修。
- **开工时一次开好全部会话**：轮数有上限，要用多少会话开工时就算得出；待命会话什么都不读，被唤醒时的缓存开销和新开一个会话一样。
- **后一批等依赖通过再开工**：上游的审查修复很快结束，下游等它通过再切出，不用逐次转告上游的修订，也没有长上下文会话闲置等待。
- **本地合并 + 一个总 PR**：子会话不推送，减少远端噪音；各块在主会话里合到一起，整体测试后再提交审阅。
- **完整报告发消息，最后只回一句**：子会话主动发消息能立刻唤醒主会话、内容完整，不用等所有子会话都停下；它自己的最后一条回复只写一句话，免得同一份报告重复占用主会话的上下文。
- **自动归档**：一次性的审查、调研会话很多，留着会堆满侧边栏；归档只清工作树，分支和提交都还在。
- **状态文件留底**：草稿目录会随会话一起被清掉；状态文件改放在本 plugin 的数据目录、以会话编号命名，事后复盘能和会话记录对上。
- **换一家模型来审**：默认 Claude 开发、Codex 审查；开发交给 Codex 时，审查改由 Claude 做。另一家模型看得出开发模型自己的盲点。
- **开发可以交给 Codex**：以往的协调里，开发会话约占 Claude 用量的八成，主会话和审查各约一成。
- **Codex 审查用它自带的审查模式**：和 Claude 审查会话调用内置 `code-review` 一样，用审查方自己的审查流程，不让它手工审。
- **分派一次，只唤醒一次**：Claude 的额度主要消耗在模型调用次数上，每调用一次都要把整份上下文重新读一遍；所以全量测试和自动返工都在脚本里完成后，才唤醒主会话。
- **Codex 开发期间心跳保活**：主会话的提示缓存闲置一小时就过期，过期后被唤醒要重写整份上下文；Codex 开发有时超过一小时，每 55 分钟心跳一次、只回一句话，花费少得多。审查很快，不设心跳。
- **Codex 限制在沙箱里**：不管你的 Codex 设置是不是完全放开，任务分派脚本都只允许它读取，或只写入这块的工作副本；提交、推送由主会话完成。

## 目录结构

```
plugins/agent-team/
├── .claude-plugin/
│   └── plugin.json         # plugin 元数据
├── skills/
│   └── lead/
│       ├── SKILL.md        # 主会话 skill
│       └── codex.sh        # 交给 Codex 审查或开发时的任务分派脚本
├── CLAUDE.md               # 贡献者指南（AI agent 改动前必读）
├── README.md               # 本文件（中文）
├── README.en.md            # 英文版
└── RELEASE-NOTES.md        # 版本历史
```

LICENSE 在 marketplace 仓库根目录，适用于本 plugin 与所有其他 plugin。

## 从 3.x 升级

4.0.0 把审查和整合审查默认交给本机的 Codex 命令行，开发仍由 Claude 的子会话做，开工时不再开审查会话。需要本机装好 Codex 并登录；想照 3.x 那样由 Claude 审查，调用时加一句「审查用 Claude」。「开发用 Codex」的用法不变。详见 [RELEASE-NOTES](RELEASE-NOTES.md)。

## 从 2.x 升级

3.0.0 新增开发交给本机 Codex 的用法和任务分派脚本；调用时不加「开发用 Codex」，用法和 2.x 相同。详见 [RELEASE-NOTES](RELEASE-NOTES.md)。

## 从 1.x 升级

2.0.0 改了整套审查修复做法：不再反复审到没有严重 bug，改为开工前定验收清单、每块审查一次、修复最多两次（复核没过才有第二次）、整合时再审一次；会话改为开工时一次开好；新增清理审查遗留问题的用法。原因见 [RELEASE-NOTES](RELEASE-NOTES.md)。

## 从 0.x 升级

1.0.0 是破坏性重写：`agent-team:teammate`、收件箱同步协议、`TeamCreate` 流程和 superpowers 开发流程参考文档全部删除，原因见 [RELEASE-NOTES](RELEASE-NOTES.md)。
